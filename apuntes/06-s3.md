## Resumen

**Amazon S3** guarda **objetos** (archivos) dentro de **buckets** (cubos). Es barato, fiable y crece sin que
haya que aprovisionar nada, y media AWS se apoya en él por debajo. Dos cosas que hay que tener claras desde
el principio: el **nombre del bucket es único en todo AWS** y **no existen las carpetas** — lo que parecen
directorios son prefijos dentro de la clave del objeto.

## Para qué se usa

- Copias de seguridad y archivado (lo más clásico: barato y duradero).
- Recuperación ante desastres, replicando entre regiones.
- Almacenamiento híbrido (unir lo local con la nube).
- Almacén de aplicaciones y de medios pesados (vídeo, audio, imágenes).
- *Data lakes* y análisis de datos: el punto donde aterriza todo.
- Distribución de software (binarios, actualizaciones, paquetes).
- **Sitios web estáticos** sin servidores.

## Buckets

- Se crean **en una región concreta**, aunque la consola haga pensar que S3 es global.
- Dos tipos: **uso general** (el de siempre) y **directorio** (optimizado para baja latencia).
- Dos espacios de nombres:
  - **Global:** el nombre debe ser único **en todas las cuentas y regiones**. Es el del vídeo.
  - **Regional de la cuenta:** único dentro de tu cuenta y región; AWS le añade un sufijo.

### Reglas del nombre

| Regla | Ejemplo que falla |
|-------|-------------------|
| 3 a 63 caracteres | `ab` |
| Solo minúsculas, números, puntos y guiones | `Demo_Curso` |
| Empieza y acaba por letra minúscula o número | `-demo-curso` |
| No puede parecer una IP | `192.168.1.1` |
| No empieza por `xn--` ni acaba en `-s3alias` | `xn--demo` |

> **Nota de precisión.** Los buckets de tipo *directorio* son **S3 Express One Zone**: viven en **una sola
> zona de disponibilidad** y su nombre lleva sufijo obligatorio. Son para latencia muy baja, no para el uso
> normal del curso ni para datos que no puedas perder si cae esa zona.

## Objetos y claves

Cada objeto se identifica por su **clave**, que es la ruta completa dentro del bucket:

```
clave = prefijo + nombre del objeto

mi-carpeta/otra/mi-archivo.txt
└──── prefijo ───┘└─── nombre ──┘
```

**No hay directorios.** La consola muestra carpetas porque agrupa por prefijos, pero por debajo solo hay
claves con barras. Crear una "carpeta" es crear un objeto vacío acabado en `/`.

| Detalle del objeto | Valor |
|--------------------|-------|
| Tamaño máximo | **5 TiB** por objeto |
| Subida multiparte | Obligatoria por encima de **5 GiB** |
| Metadatos | Pares clave-valor con información del objeto |
| Etiquetas | Para automatizar, repartir costes y aplicar políticas |
| ID de versión | Solo si el **versionado** está activado |

> **Nota de precisión.** En el vídeo se dice que un objeto puede pesar **50 TB**. El límite real de S3 es
> **5 TiB** por objeto (y 5 GiB por subida simple). Lo que no tiene límite es el bucket.

## Demo: crear el bucket y subir objetos

1. **Región**: la que tengas seleccionada. **Tipo**: uso general. **Espacio de nombres**: global.
2. **Nombre único**. Si está cogido, la consola responde que ya existe un bucket con ese nombre.
3. **Bloquear todo el acceso público** (recomendado, y activado por defecto).
4. **Versionado**: desactivado en la demo.
5. **Cifrado**: el de lado de servidor con claves gestionadas por S3 (SSE-S3), que ya viene puesto.
6. Subir un archivo, crear la "carpeta" `images/` y subir otro dentro.

```bash
aws s3 mb s3://mi-bucket-unico-del-curso --region us-east-1
aws s3 cp cafe.jpg s3://mi-bucket-unico-del-curso/images/cafe.jpg
aws s3 ls s3://mi-bucket-unico-del-curso --recursive
```

### Las dos URLs del objeto

| URL | Qué es | Resultado con el bucket bloqueado |
|-----|--------|-----------------------------------|
| *Abrir* desde la consola | URL **prefirmada**: lleva una firma con tus permisos y caduca | Se ve |
| *URL del objeto* | URL pública `https://<bucket>.s3.<region>.amazonaws.com/<clave>` | **AccessDenied** |

Es la confusión típica del principio: el objeto se ve desde la consola y no se ve al pegar la URL. No es un
error, es que el acceso público está bloqueado.

```bash
aws s3 presign s3://mi-bucket-unico-del-curso/mi-archivo.txt --expires-in 3600
```

> **Nota de precisión.** Para publicar de verdad hacen falta **dos cosas**: quitar el bloqueo de acceso
> público **y** poner una **política de bucket** que permita `s3:GetObject` al principal `*`. Un ejemplo
> está en [`politica-bucket-lectura-publica.json`](../06_s3/politica-bucket-lectura-publica.json). Para una
> web pública, lo razonable es dejar el bucket privado y servirlo con **CloudFront**.

### Borrar

Se borran objetos y "carpetas" desde la consola escribiendo la confirmación que pide. Con el versionado
activado, borrar deja un **marcador de borrado**: el objeto deja de verse, pero las versiones siguen ahí
(y siguen pagándose) hasta que se vacían.

## Errores típicos

- Elegir un nombre de bucket ya cogido por otra cuenta del mundo.
- Pensar que las carpetas existen y esperar operaciones de directorio.
- Pegar la URL pública de un objeto de un bucket bloqueado y creer que algo falla.
- Quitar el bloqueo de acceso público "para probar" y dejar el bucket abierto.
- Activar el versionado y olvidar que las versiones antiguas también ocupan y cuestan.
